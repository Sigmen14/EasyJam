# Инструкции для ИИ-помощника --- Unity Project

Этот файл содержит правила работы ИИ-помощника с проектом. Соблюдай их
при чтении, создании и изменении кода и файлов.

## 1. Сначала изучи проект

-   Перед изменениями осмотри структуру проекта и связанные скрипты,
    сцены, префабы и настройки.
-   Ищи существующие решения и расширяй их, вместо того чтобы создавать
    дублирующие системы.
-   Если в репозитории есть документы с требованиями к игре (например,
    папка `Instructions`), прочитай их и считай главным источником
    требований.
-   При противоречии между этим файлом и игровыми требованиями приоритет
    имеют актуальные требования проекта.
-   Не придумывай игровые механики, правила, интерфейс или архитектуру.
    Если важная деталь не определена, задай короткий уточняющий вопрос.

## 2. Unity и C

-   Проект использует Unity 6 и 2D (Universal 2D), если настройки
    проекта не указывают иное.
-   Пиши понятный, аккуратный и поддерживаемый C# код.
-   Используй существующий стиль именования и структуру папок проекта.
-   Не добавляй сторонние пакеты и зависимости без необходимости и
    согласования.
-   Не меняй настройки проекта, Input System, Render Pipeline, Physics
    2D или пакеты без объяснения причины.
-   Проверяй ссылки на компоненты и объекты; не полагайся на случайный
    порядок выполнения скриптов.
-   Избегай `FindObjectOfType`, `GameObject.Find` и других глобальных
    поисков в часто вызываемом коде, если можно использовать
    сериализованные ссылки или явную передачу зависимостей.
-   Не создавай сложную архитектуру ради простых задач. Предпочитай
    простые решения, которые легко понять новичку.
-   Не используй устаревшие API Unity, если есть актуальная
    альтернатива.

## 3. Безопасность изменений

-   Изменяй только файлы, необходимые для поставленной задачи.
-   Не удаляй и не переименовывай сцены, префабы, ассеты, скрипты или
    папки без явной необходимости.
-   Не перезаписывай существующую работу пользователя.
-   Не меняй `.gitignore`, `Packages/manifest.json`, `ProjectSettings` и
    настройки сборки без объяснения.
-   Не редактируй вручную файлы в `Library/`, `Temp/`, `Obj/`, `Logs/` и
    `Build/`. Это генерируемые папки Unity.
-   Не добавляй в Git временные файлы, кэш, логи и результаты локальной
    сборки.

## 4. Работа с Git

-   Не выполняй `commit`, `push`, `pull`, `reset`, `rebase`, `checkout`
    или другие Git-операции без прямой просьбы пользователя.
-   Не удаляй и не откатывай пользовательские изменения.
-   Перед предложением коммита кратко перечисли, какие файлы изменены и
    зачем.
-   Не советуй коммитить все изменения автоматически: Unity может менять
    служебные файлы настроек.
-   Сохраняй существующие `.meta` файлы Unity. При добавлении или
    перемещении ассетов учитывай связанные `.meta` файлы.

## 5. Как выполнять задачи

1.  Кратко определи, что нужно изменить.
2.  Проверь связанные файлы и текущую реализацию.
3.  Сделай минимальное необходимое изменение.
4.  Проверь код на очевидные ошибки и несовместимости с используемой
    версией Unity.
5.  В конце сообщи:
    -   что именно изменено;
    -   какие файлы затронуты;
    -   что нужно проверить в Unity Editor вручную;
    -   есть ли ограничения или нерешённые вопросы.

## 6. Общение

-   Объясняй действия простым языком, так как пользователь может быть
    новичком в Unity и программировании.
-   Не перегружай ответ сложными терминами.
-   Если нужно выполнить действие в Unity Editor, давай пошаговую
    инструкцию: куда нажать и что должно появиться.
-   Не утверждай, что запускал игру, тесты или проверял сцену в Unity,
    если фактически этого не делал.
-   Если не уверен --- прямо скажи об этом и уточни нужную информацию.

## 7. Главное правило

Сохраняй существующий проект и его задумку. Делай небольшие, понятные и
проверяемые изменения. Не усложняй игру и не меняй требования
самостоятельно.
